# UPPETIT TV - Android Player

Профессиональное клиентское приложение для систем Digital Signage (Android TV). 
Разработано для сети торговых точек **UPPETIT**.

---

## 🚀 Основные возможности
*   **Kiosk Mode / Launcher**: Автозапуск при включении устройства. Приложение блокирует стандартный интерфейс Android TV.
*   **Offline-First**: Контент сначала полностью кэшируется во внутреннюю память, затем воспроизводится. Не зависит от стабильности интернета.
*   **Hybrid Player**: Бесшовное переключение между видео (ExoPlayer) и статичными изображениями (Glide).
*   **Centralized Control**: Полное управление через WebSocket (плейлисты, скриншоты, перезагрузка, OTA-обновление).
*   **Security**: Двухфакторная авторизация устройства (Short ID + Unique Device Secret).
*   **Monitoring**: Отправка отчетов о проигрывании (Event Logging) и скриншотов эфира на сервер в реальном времени.

## 🛠 Технологический стек
*   **Kotlin** (Android SDK 29+)
*   **Media3 (ExoPlayer)** - для видео
*   **Glide** - для оптимизированной работы с фото
*   **OkHttp & WebSockets** - для связи с сервером

## 📦 Как настроить и собрать проект
1.  **Настройка сервера:** Откройте файл `app/src/main/java/com/uppetit/tv/MainActivity.kt`. Найдите функцию `connectWebSocket` (примерно 230-я строка) и замените тестовый адрес `wss://ws.postman-echo.com/raw` на ваш рабочий адрес WebSocket-сервера.
2.  **Настройка фонового видео:** В том же файле найдите переменную `defaultVideoUrl` (в начале класса) и укажите ссылку на видео, которое должно проигрываться на фоне экрана ожидания (где отображается ID).
3.  **Сборка APK:** 
    *   **Debug:** `Build -> Build Bundle(s) / APK(s) -> Build APK(s)`.
    *   **Release:** `Build -> Generate Signed Bundle / APK...` (используйте один и тот же файл ключа `.jks` для всех последующих обновлений).

## 🔄 Как выпускать обновления (OTA)
Для успешного удаленного обновления приложения необходимо соблюдать два правила:
1.  **Увеличение версии:** В файле `app/build.gradle.kts` измените `versionCode` на большее значение (например, с 1 на 2).
2.  **Тот же ключ подписи:** Всегда используйте один и тот же файл Key Store (`.jks`) и тот же Alias. Если подписать обновление другим ключом, Android заблокирует установку поверх старой версии.

## 📖 Спецификация интеграции (для Веб-разработчика)

### 1. Архитектура
Система работает через постоянное WebSocket-соединение.
- **Client (Android TV):** Подключается к серверу, сообщает свой статус и ждет команд.
- **Server:** Транслирует команды от администратора к ТВ по `device_id`.

### 2. Безопасность (Security)
Для предотвращения несанкционированного доступа используется двухфакторная модель:
1.  **Short ID (человеческий):** 6-значный код (например, `A8K 2M9`) для визуального сопряжения.
2.  **Device Secret (технический):** Уникальный UUID-токен, который генерируется приложением при первом запуске и передается в каждом логе/телеметрии.
**Важно:** Сервер должен навсегда связать `Short ID` и `Device Secret` при первом сопряжении.

### 3. WebSocket Протокол (JSON)

#### 3.1. Телеметрия при подключении (ТВ -> Сервер)
Отправляется сразу после установки связи.
```json
{
  "device_id": "A8K 2M9",
  "device_secret": "UUID-TOKEN-HERE",
  "status": "online",
  "system": { "android_version": "13", "app_version": "1.0" },
  "storage": { "available_gb": 12.45, "total_gb": 16.00 },
  "network": { "ip_address": "192.168.1.50" }
}
```

#### 3.2. Обновление плейлиста (Сервер -> ТВ)
ТВ скачивает файлы локально перед запуском.
```json
{
  "command": "UPDATE_PLAYLIST",
  "playlist": [
    { "id": "v1", "type": "video", "url": "https://cdn.url/video.mp4" },
    { "id": "i1", "type": "image", "url": "https://cdn.url/pic.jpg", "duration_seconds": 15 }
  ]
}
```

#### 3.3. Удаленное обновление приложения (OTA)
```json
{ "command": "OTA_UPDATE", "url": "https://cdn.url/app-v2.apk" }
```
*На ТВ откроется системное окно подтверждения установки.*

#### 3.4. Служебные команды
- `{"command": "SCREENSHOT"}` -> ТВ вернет JSON с типом `SCREENSHOT_RESULT` и картинкой в Base64.
- `{"command": "REBOOT"}` -> Полный перезапуск приложения.

### 4. Требования к Бэкенду
- **WebSocket Server:** Хранение связок `device_id` <-> `Socket`.
- **Static Storage:** CDN для видео/фото с поддержкой прямых ссылок и заголовка `Content-Length`.
